# Verification

What was checked, how, and what is still open. The plan is [docs/spec/VERIF_PLAN.md](https://github.com/NotCleo/JS-PE/blob/main/docs/spec/VERIF_PLAN.md); results are in [PROGRESS.md](https://github.com/NotCleo/JS-PE/blob/main/PROGRESS.md) (test status, sign-off record, area ledger), [formal/RESULTS.md](https://github.com/NotCleo/JS-PE/blob/main/formal/RESULTS.md) (generated by `make formal`) and [docs/IR_DROP.md](https://github.com/NotCleo/JS-PE/blob/main/docs/IR_DROP.md). Nothing has been tested on silicon or on a demo board: every protocol figure below is from simulation.

## 1. Strategy in one paragraph

A cycle-accurate Python ISS ([sw/jspe_iss.py](https://github.com/NotCleo/JS-PE/blob/main/sw/jspe_iss.py)) was written from the spec before any RTL and every program was proven on it against protocol models that share no code with it. The RTL was then written to match the ISS clock for clock, and the top-level cocotb tests compare all 24 output pad bits against the ISS in every clock (lockstep) while independent bus models check the protocol on the pads. Formal proofs (k-induction) cover every block except the ALU and the memory against properties transcribed from the spec, and mutation testing checks that the proofs can fail. The same 45 system tests then ran on the post-layout netlist.

The weak point is shared: ISS and RTL come from the same reading of the spec. The independent protocol models, the formal properties written from ARCH.md, and a reviewer pass per block and per protocol are the counterweights (VERIF_PLAN 13).

## 3. Formal results per block

From [formal/RESULTS.md](https://github.com/NotCleo/JS-PE/blob/main/formal/RESULTS.md) (2026-11-19). Properties = assertions + helper invariants, all PASS; method per block in [formal/PLAN.md](https://github.com/NotCleo/JS-PE/blob/main/formal/PLAN.md) and D106–D118.

| Block | Properties | Depth | Covers | Mutants caught | Environment assumptions |
|---|---|---|---|---|---|
| arb | 15 | k-induction k=4 | 20 | 6/6 | none beyond the constant slot map |
| seq | 56 (47 + 9 helpers) | k=1 (decoder vs isa.yaml), 2, 3, 7 (fetch latency) | 83 | 47/49, 2 equivalent | arbiter behaviour (proven in arb); host rules discharged by link proofs |
| pins | 10 | k=4 | 15 | 20/20 | none, every input free |
| epins | 9 | k=2 | 17 | 26/26 | none |
| fifo | 8 | k=2, W = 8 and 9 | 10 | 14/14 | flush in step 0 only |
| link | 20 | k=2 (+ bmc 16 on receiver-cut tasks) | 28 | 34/34 | host bit stream free: holds for any host behaviour |
| top | 4 | k=4 from an arbitrary state; whole-chip idle bmc 40 | 5 | 6/6 | none (other blocks cut to free outputs) |
| timer | 10 | k=2 | 14 | 18/18 | none |
| shift | 7 | k=2 | 8 | 21/21 | none |
| sig | 5 | k=2 | 5 | 8/8 | none |
| lfsr | 5 | k=2 | 6 | 11/11 | none |

What the top-level proof gives: from any state, reset reaches the reset values with no X, and no pad drives until the host enables it (a_rst, a_safe). The link proofs show the D107 host obligations of the sequencer hold for *any* host, so no host rule is needed for them. Not covered formally: `jspe_alu` (engine lockstep only), `jspe_mem`, and anything at protocol level.

## 6. How to rerun

| Claim | Command |
|---|---|
| lint clean | `make lint` |
| ISS/toolchain tests | `make swtest` (`make swtest-all` includes the slow ones, > 20 s each) |
| block tests | `make unit B=jspe_arb` (… `jspe_engine`, `jspe_fifo`, `jspe_lfsr`, `jspe_link`, `jspe_pins`, `jspe_sig`) |
| 45 system tests | `make test` |
| formal | `make formal B=<block>` (arb, seq, pins, epins, fifo, link, top, timer, shift, sig, lfsr) |
| mutation | `make mutate B=<block>` |
| gate level | `make gl-fetch RUN=44625407065`, then `make gl-all` |
| area | `make area LIB=<sg13g2 typ liberty>` |

## 7. Known gaps

Stated as found in PROGRESS.md and VERIF_PLAN 13 (2026-11-20):

| Gap | Effect |
|---|---|
| No silicon, no board run | every rate and timing figure is from ISS, RTL or gate-level simulation; `host/` has never run on an RP2350 |
| No RTL code coverage | VERIF_PLAN 10 asks for ≥ 95 % line coverage; not measured |
| ISS functional coverage bins | planned in VERIF_PLAN 10, not collected |
| Not run at RTL: H3, H6, C1, MON1, EI1 (EI1/MON1 are SHOULD) | these exist at ISS level or not at all; RND1 ran 26 seeds, not the planned ≥ 200 |
| No block tests for `jspe_mem`, and none separately for `jspe_alu`/`timer`/`shift`/`epins`/`seq` | covered through engine lockstep and the system tests; formal covers seq, timer, shift, epins |
| `jspe_alu` and `jspe_mem` have no formal proofs | lockstep only |
| 2 max-slew violations in the slow corner | VERIF_PLAN 9 asks for zero; D082 design repair cut them from 17 to 2 (run 5), none fixed since; precheck passes |
| IR drop is a hand estimate | no vector-based activity; combined worst case 5.4 % |
| Metastability not simulated | the synchronizer is checked structurally only |
| ISS and RTL share one reading of the spec | countered by independent models, formal, reviewer passes |
